# Behaviour inventory of the legacy test modules (WP0)

One row per distinct asserted behaviour in `tests/test_poc.py`, `tests/test_fedavg_readiness.py`, `tests/test_exchange.py`,
`tests/test_exchange_hardening.py` and `tests/test_hf_webhook_relay.py`, extracted while those modules still run against the
legacy package. Multi-scenario tests yield several rows; fixture helpers whose assertions every test relies on (`setUp`,
`member`, `ready`, `upload`, `sdk`) are listed under their helper name. Error codes, states, messages and numbers are quoted
exactly as asserted; a code the target design renames is noted inline as `(target: ...)`.

Columns: `id` (S-001...), `source` (legacy `module::test`, module name without `.py`), `area`, `behaviour` (one sentence),
`covered by` (an executable retained test or an explicitly superseding test). V3 keeps the legacy exchange
service and its frozen adapter/owner test fixtures as historical regression evidence. A `legacy:` entry does **not**
claim that the new `/v2` service exposes the same API, errors, or state names. New exchange behavior is verified by
`packages/exchange/tests`; the correspondence below records the tests actually retained rather than inventing a
one-to-one replacement. `test_architecture_v3` checks that every inventory entry still names a real test/helper.

Areas, in table order: `checkpoint`, `common`, `core`, `examples`, `plugins`, `client`, `owner`, `hf`, `jfrog`,
`exchange-auth`, `exchange-domain`, `exchange-upload`, `exchange-claims`, `exchange-worker`, `exchange-settings`, `sdk`,
`adapter`, `cli`, `relay`. Rows tagged `(race)`, `(lost-response/resume)` and `(blob-lease)` in the behaviour column form
the named groups indexed at the end of the file.

## V3 interpretation

The S-001 through S-250 descriptions above are frozen observations of the original implementation. References to
"the target" describe the historical rewrite proposal, not the accepted V3 design. V3 preserves current FL filenames,
legacy command entry points, and the standalone exchange `/v2` contract. It does not implement the proposed incompatible
`/v1` rewrite or client-supplied workflow language.

S-050 is intentionally superseded for automatic v2 rounds: malformed or incompatible candidates may be skipped while
at least two valid frozen participants remain; explicit candidate selection still fails on invalid input. The frozen
legacy end-to-end test continues to prove its old fail-and-release behavior. The actual v2 end-to-end test verifies
that the published record names exactly the two usable inputs and contains their correctly weighted checkpoint.

The independent service suite is the current contract oracle for immutable schemas, present authorization, generic
records, fenced acquisitions, exact-version storage, and crash/repair behavior. In particular:

| New contract | Executable evidence |
|---|---|
| Generic metadata and reference names | `packages/exchange/tests/test_integration.py::test_arbitrary_document_types_filenames_and_named_references` |
| Immutable schema and publication policy | `packages/exchange/tests/test_integration.py::test_schema_revision_is_immutable_and_draft_keeps_original_revision`; `packages/exchange/tests/test_integration.py::test_current_policy_rechecked_at_publication_without_retargeting_schema` |
| Member revocation and isolation | `packages/exchange/tests/test_integration.py::test_roles_visibility_revocation_and_cross_space` |
| Fenced inputs and completion replay | `packages/exchange/tests/test_integration.py::test_coordination_keys_freeze_inputs_fence_stale_attempts_and_replay_completion` |
| Physical quota after interrupted mutation | `packages/exchange/tests/test_recovery.py::test_cancelled_crash_keeps_physical_quota_until_operator_repair_and_cleanup` |
